How JavaScript Hoisting Works (and Why It Matters)

Hoisting is one of those JavaScript words that sounds scary but is actually easy to understand. In simple words, JavaScript prepares some declarations before your code starts running — and that can change what your program does.

Hoisting is JavaScript's way of making declarations available before the line where they appear in your code. That is why some functions can be used before they are written, while some variables behave differently depending on whether you used var, let, or const [web:20][web:23].

TL;DR

JavaScript seems to move declarations to the top of their scope. Function declarations work early, var gives undefined, and let/const can throw errors if used too soon [web:20][web:25][web:28].

1. What hoisting really means

A simple way to think about hoisting is this: before JavaScript runs your code, it reads the declarations first. That does not mean it moves your code around in the file. It just means JavaScript sets things up in memory before execution begins [web:20][web:23].

So when people say “JavaScript hoists variables,” they mean the declarations are handled early, not physically relocated in your source file [web:20].

2. A kid-friendly idea

Imagine a teacher writes all the student names on a board before class starts. The names are ready, but some students are not allowed to answer questions until their turn comes. That is similar to hoisting: the names exist early, but not all of them can be used the same way.

3. The easy examples

javascript — function declaration
sayHello();

function sayHello() {
  console.log("Hello!");
}

This works because function declarations are hoisted with their full definition, so JavaScript already knows what sayHello means when it reaches the first line [web:23].

javascript — var hoisting
console.log(name); // undefined

var name = "Akash";

console.log(name); // Akash

Here, var name is hoisted, but only the declaration is prepared early. The value "Akash" is still assigned later, so the first log gives undefined [web:19][web:26].

javascript — let and const
console.log(age); // ReferenceError

let age = 20;

With let and const, the variable is also hoisted, but it is not ready to use until the declaration line runs. If you try to read it too early, JavaScript throws a ReferenceError [web:11][web:25][web:28].

4. Why this matters

Hoisting matters because it affects how your code behaves before and after declarations. If you do not understand it, you might expect undefined but get an error, or expect an error but get a value you did not mean to use.

That is why hoisting is a common source of bugs for beginners and even experienced developers. A small misunderstanding can lead to broken logic, especially in large files with many functions and variables [web:22][web:25].

5. var vs let vs const

The biggest difference is not just hoisting — it is how each keyword behaves after hoisting. var is function-scoped and initialized with undefined, while let and const are block-scoped and stay unavailable until their declaration runs [web:19][web:28].

javascript — side by side
console.log(a); // undefined
var a = 10;

console.log(b); // ReferenceError
let b = 10;

console.log(c); // ReferenceError
const c = 10;

This is also why many developers prefer let and const over var. They make early mistakes more visible instead of silently returning undefined [web:25][web:28].

6. The TDZ connection

Hoisting and the Temporal Dead Zone are closely connected. For let and const, the variable is hoisted but cannot be used during the time between entering the scope and reaching the declaration line. That waiting period is the TDZ [web:11][web:25].

So if hoisting is the “early preparation,” TDZ is the “not ready yet” phase. Together, they explain why some variables work early and others do not.

7. A common mistake

javascript — confusing example
function demo() {
  console.log(score); // undefined
  var score = 5;

  console.log(level); // ReferenceError
  let level = 2;
}

In this example, score is hoisted with var, so the first log gives undefined. But level is a let, so it cannot be used before the declaration line [web:19][web:25][web:28].

8. The safest habit

The safest way to write JavaScript is to declare variables before using them. Put function declarations near the top of the file when it makes sense, use let and const instead of var, and do not rely on hoisting for clarity.

Good habit

Write code so it reads in the same order you expect it to run.

Summary

Hoisting is JavaScript's way of preparing declarations before execution starts. It helps explain why functions can be called early, why var can become undefined, and why let and const can throw a ReferenceError [web:20][web:23][web:25].

If you remember one thing, remember this: declare first, use second. That simple habit will save you from many hoisting-related bugs.
